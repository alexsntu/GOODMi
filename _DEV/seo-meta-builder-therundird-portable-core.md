## Приоритет поисковика: только Google

В отличие от GOODMi (Yandex 58% / Google 41%), для US-аудитории — один основной канал: **Google**. Bing даёт единицы процентов трафика в большинстве e-commerce ниш США — не оптимизировать под него отдельно, если пользователь явно не попросит.

Длина title — ориентир **50–60 симв.** (Google SERP визуально обрезает ~580px / ~60 симв.), но по методологии оригинала: **не жертвовать ключами ради визуального лимита** — поисковик индексирует полный title, обрезание в SERP не влияет на ранжирование. Важные слова — в начале, «| TheRundird» — в конце, допускается к обрезанию.

---

## Geo-стратегия — вероятно не нужна

GOODMi — локальный магазин с самовывозом (Крым), поэтому гео было обязательным сигналом. TheRundird — судя по описанию, доставка по всей стране без физических точек самовывоза → **гео в H1/title не нужен**, если только:
- нет производства/мастерской в конкретном городе/штате, которое стоит подсвечивать как E-E-A-T-сигнал («handmade in [штат]»)
- нет отдельной задачи ранжироваться по locality-запросам (маловероятно для нишевого handmade-магазина с доставкой)

Если гео всё же нужен — уточнить перед началом работы, куда именно (штат производства vs «USA-wide shipping» как USP, это разные вещи).

## Workflow (адаптированный порядок)

### Step 1 — Разбор запроса

Извлечь: тип страницы (категория аксессуаров / серия под конкретную деталь авто / конкретный SKU), есть ли данные по ключевым словам от пользователя, batch или одна страница.

Мультибренд-блокер (Step 2e оригинала) — **не переносить**, если TheRundird продаёт только собственные хендмейд-товары под одним брендом. Если в ассортименте появятся сторонние бренды/партнёры — тогда адаптировать логику флагов 🎯/👁/— по офиц. магазинам конкурентов.

---

### Step 2 — SERP research (WebSearch, английские запросы)

Заменить русские шаблоны на:
1. `"buy [product] c6 corvette"` — прямой коммерческий запрос
2. `"[product] corvette c6 accessories"` — категорийный вариант
3. `"[product] c6 corvette handmade"` / `"custom [product] corvette c6"` — если нишевый handmade-сигнал важен для дифференциации

Опционально (для FAQ-семян, как в оригинале):
4. `"how to choose [product] for c6 corvette"`

**Фильтр агрегаторов/маркетплейсов США** (аналог блока в оригинале) — исключить из анализа title:
```
amazon.com · ebay.com · etsy.com (спорно — many handmade sellers there, оценить отдельно)
walmart.com · summitracing.com · corvette-accessories вертикальные маркетплейсы — оценить по факту
```
Etsy может быть не чистым агрегатором для handmade-ниши — конкуренты там могут быть релевантны для gap-анализа, не исключать автоматически.

**Приоритетные конкуренты** — собрать список специализированных C6 Corvette accessory shops по факту SERP (в оригинале был статичный список mi-shop.com и т.п. — для новой ниши список нужно строить с нуля, нет готового).

---

### Step 2b — Оценка спроса (замена Wordstat-кластера)

Wordstat недоступен → используется тот же **fallback**, что в оригинале уже описан как запасной путь (Step 2b, «Когда Wordstat недоступен»), но здесь он становится **основным**:

**1. SERP-частота (аналог первой fallback-таблицы оригинала):**

| Частота ключа в title/H1 реальных конкурентов топ-10 | Оценочная значимость |
|---|---|
| 3+ упоминаний | ~50 — кандидат в title |
| 1–2 упоминания | ~20 — кандидат в description |
| 0 упоминаний | < 15 — пропустить |

**2. Ручная проверка Google Trends** — сравнить относительный интерес (0–100) между вариантами формулировки кандидата (например «corvette c6 shift knob» vs «corvette c6 shifter knob»). Как и в Wordstat-логике оригинала — это **относительное** сравнение вариантов между собой, не абсолютная величина спроса.

**3. Ручная проверка Google Autocomplete / «People also ask»** — заменяет quoted-частоту Wordstat как демонд-фильтр для USP-фраз: ввести `[термин] + [USP]` в поиск Google, посмотреть — предлагает ли автодополнение эту комбинацию, есть ли она в «People also ask». Есть сигнал → фраза оправдана в description. Нет → не вставлять, место лучше отдать характеристикам товара (материал, совместимость по годам/комплектации).

Формула взвешенного балла по гео-каскаду (Севастополь×0.55 и т.д.) — **не переносится**, гео-измерения нет.

---

### Step 2c — Gap Analysis конкурентов

Переносится **без изменений по структуре** (SERP-сниппеты → при необходимости WebFetch на ★-конкурента). Таблица извлечения (H1/title, FAQ, schema, USP, конкретные числа, слабые места) универсальна для любой ниши/языка.

---

### Step 2d — Информационный SERP (для AI Overviews / ChatGPT Search / Perplexity)

Переносится с заменой запросов:
1. `"how to choose [product] for c6 corvette"`
2. `"best [product] for corvette c6 [year]"`
3. `"[product A] vs [product B] corvette c6"`

Цель та же — найти информационные запросы, где TheRundird может быть процитирован AI-поисковиками. В нишевом handmade-сегменте шанс попасть в AI Overview часто выше, чем в масс-маркете (меньше конкуренции за информационный контент).

---

### Step 3 — Генерация тегов

**H1/title/description — структурные правила по длине и AEO-паттерну переносятся без изменений**, только:
- убрать все инструкции про двойное гео / кириллицу / «Севастополь первым»
- title-ориентир: 50–65 симв. (Google-only, без запаса под Yandex-70)
- description: сохранить CS-Cart жёсткий лимит 255 симв., целевая длина 180–250 (как в оригинале — платформа та же)
- E-E-A-T приоритеты адаптировать: Trustworthiness → замена «гарантия 1 год» на актуальный USP TheRundird (например «lifetime warranty» или «made to order» — что реально есть); Expertise → «handmade C6 Corvette accessories specialist» вместо «фирменный магазин Xiaomi»; Experience → «since [год]» вместо «с 2016 года»; Authoritativeness → заполнить по факту (упоминания в Corvette-форумах/клубах, если есть)

**Approved USPs — заменить полностью на реальный список TheRundird** (гарантия/доставка/трейд-ин/кредит GOODMi не имеют отношения к новому бизнесу).

**Демонд-фильтр USP** — таблица из оригинала (Step 4 «USP-фильтр») переносится по структуре, колонка «Quoted-частота Wordstat» заменяется на «Autocomplete/PAA сигнал: да/нет».

---

### Step 4 — Проверка перед выводом

Чек-лист переносится с вычеркиванием строк: двойное гео, кириллица, sameAs→Яндекс Карты, PixelPlus. Остальное (длина H1/title/description, AEO-паттерн, порядок хвоста, каннибализация в batch, антиспам синонимов) — универсально.

---

### Step 5 — Output format

Формат вывода (H1/title/description в отдельных code-блоках для копирования) — переносится без изменений, это уже подтверждённая пользователем практика ([[feedback-meta-output-format]]).

`sameAs` в LocalBusiness JSON-LD — если у TheRundird есть верифицированный профиль Google Business / соцсети, использовать его вместо Яндекс Карт. Если профиля нет — убрать поле, не выдумывать.

---

### Step 6 — Семантическое ядро

Переносится с заменой:
- нижний регистр, без пунктуации — тот же стандарт для Google Search Console (не только Яндекс Вебмастера)
- Tier 1/2/3 логика (🎯 цели / 👁 мониторинг / длинный хвост по числу агрегаторов в топ-10) — переносится без изменений, это Google SERP-агностичный принцип
- Убрать «рассрочка», «трейд-ин», кириллические хвосты — заменить на реальные условия покупки TheRundird (если есть layaway/financing — свой аналог)

**Step 6a (отправка в PixelPlus)** — не переносится, если нет аналогичного трекинг-инструмента для US. Если появится (Ahrefs Rank Tracker, SEMrush Position Tracking, Google Search Console сам по себе) — адаптировать по аналогии.

**Step 6b (мониторинг нейроответов)** — переносится полностью, чек-лист универсален (Google AI Overview + ChatGPT Search вместо Яндекс Нейро + Google AI Overview).

## Что решить в новом проекте перед первым запуском скилла

1. Точные brand constants (см. плейсхолдеры вверху)
2. Есть ли локальный гео-сигнал (мастерская/производство) или чисто nationwide-shipping бренд
3. Реальный список Approved USPs (что предлагает TheRundird на деле — гарантия? handmade-статус? made-to-order сроки?)
4. Инструмент трекинга позиций (аналог PixelPlus), если нужен Step 6a
5. Есть ли у TheRundird schema.org Product/Offer разметка уже — насколько строгие технические запреты CS-Cart (@graph, FAQPage) реально нужно соблюдать (они наследуются от платформы, не от GOODMi — но их стоит перепроверить, а не копировать слепо)
