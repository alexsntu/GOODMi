### 5. SSH к серверам (те же ключи, что у `a0000`)

Решение пользователя 2026-10-14: использовать ключи `a0000`, а не заводить новые (на одном Mac разница в безопасности
небольшая; минус – отзыв ключа отключит обе учётки). Выполнять **только в Терминале учётной записи `alex-max`**:
2026-10-14 этот блок по ошибке запустили в `a0000` – ключи сменили владельца и SSH там сломался (восстановлено).

```bash
[ "$(whoami)" = "alex-max" ] || { echo "Это не alex-max – стоп"; return 2>/dev/null; exit; }
mkdir -p ~/.ssh && chmod 700 ~/.ssh
sudo cp /Users/a0000/.ssh/goodmi_ed25519 /Users/a0000/.ssh/goodmi_ed25519.pub /Users/a0000/.ssh/price_maxmobiles_ed25519_new /Users/a0000/.ssh/price_maxmobiles_ed25519_new.pub /Users/a0000/.ssh/known_hosts /Users/a0000/.ssh/config ~/.ssh/
sudo chown alex-max:staff ~/.ssh/goodmi_ed25519* ~/.ssh/price_maxmobiles_ed25519_new* ~/.ssh/known_hosts ~/.ssh/config
chmod 600 ~/.ssh/goodmi_ed25519 ~/.ssh/price_maxmobiles_ed25519_new ~/.ssh/known_hosts ~/.ssh/config
ssh goodmi hostname          # ответ: mmnew
ssh price-maxmobiles hostname   # ответ: price.maxmobiles.ru
```

**Выполнено 2026-10-14, две поправки к блоку выше:**
- `alex-max` – не администратор, `sudo` в ней не работает. Копировали из Терминала `alex-max` через `su a0000 -c 'sudo cp … /Users/alex-max/.ssh/ && sudo chown alex-max:staff …'` (пароль учётки a0000 дважды; все пути полные, без `~`).
- Первая строка `config` – `Include /Users/a0000/.colima/ssh_config` (Colima есть только у `a0000`): в `alex-max` из-за неё SSH падает с `Bad owner or permissions`. В копии `alex-max` строка закомментирована (бэкап `~/.ssh/config.bak`). При повторном копировании `config` – снова закомментировать.

`~/.ssh/config` копируется целиком (без многострочного ввода – при вставке heredoc Терминал «зависает» на `heredoc>`).
Через VPN HAPP SSH к 176.123.171.223 не проходит – нужен маршрут в обход (команду с `sudo` запускает пользователь):
`sudo route -n add -host 176.123.171.223 $(ipconfig getoption en0 router)`.

## Правила попеременной работы

1. **Не запускать Claude в обеих учётных записях одновременно** – общая память и рабочие файлы могут перезаписать друг друга.
2. **Перед сменой учётной записи – закоммитить** («закоммить всё») и сказать «запомни всё» – тогда во второй
   учётной записи Claude увидит и историю git, и заметки.
3. Новую сессию начинать с «с чего продолжаем?» – Claude прочитает раздел «С чего продолжить» в памяти.
4. Разрешения инструментов (`~/.claude/settings.json`) у каждой учётной записи свои – в `alex-max` Claude первое время
   будет чаще спрашивать подтверждение.
