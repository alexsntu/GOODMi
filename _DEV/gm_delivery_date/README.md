# Модуль «GOODMi: сроки получения товара» (`gm_delivery_date`)

Показывает покупателю, когда товар можно забрать в пункте выдачи, когда его привезёт курьер и когда доставит
СДЭК. Сроки считаются по остаткам на складах, городу покупателя и текущему времени. Работает на витрине GOODMi
в карточке товара (ПК и телефон), каталоге, корзине и на оформлении заказа.

Сделан и установлен 2026-10-07. Правила продиктованы владельцем магазина; их сводка – в `RULES.md`.

## Что где лежит

| Путь | Что это |
|---|---|
| `RULES.md` | Все правила словами и таблицами – читать первым, если нужно понять «почему показало такую дату» |
| `engine.php` | Расчёт дат. Чистый PHP без CS-Cart, чтобы его можно было проверять отдельно |
| `tests.php` | 48 проверок правил (границы времени, рейсы, выходные, праздники). Запуск: `php tests.php` |
| `integration-check.php`, `integration-check-cart.php` | Проверки на настоящей базе магазина, только чтение |
| `styles.css` | Стили блоков (на сайте это секция 28 «Своего CSS» GOODMi) |
| `addon/` | Файлы модуля в том виде и по тем путям, как они лежат на сервере |

Точные копии серверных файлов дополнительно хранятся в `server-overrides/` (там же общий порядок восстановления).
`addon/app/addons/gm_delivery_date/lib/engine.php` – копия `engine.php`; правим `engine.php`, затем копируем.

## Как это работает

1. На страницах GOODMi подключается скрипт `js/addons/gm_delivery_date/func.js`. Шаблоны магазина не меняются.
2. Скрипт находит на странице товары и запоминает, куда вставить блок:
   - карточка товара, ПК – в конец блока покупки `.ut2-pb__main-content-box`;
   - карточка товара, телефон – после кнопки `.ut2-pb-mobile .ut2-pb__button` (у телефонов отдельный шаблон);
   - каталог, витрины, избранное – после строки «В наличии» `.ut2-gl__amount` в карточке `.ut2-gl__item`;
   - корзина – после кода товара в строке таблицы.
   Номер товара берётся из скрытого поля формы `…[product_id]`.
3. Одним запросом `index.php?dispatch=gm_delivery_date.estimate&ids=1,2,3` скрипт спрашивает сроки для всех
   найденных товаров. Сервер отвечает готовой разметкой в трёх видах: `card`, `line`, `cart`.
4. Сервер (`func.php`):
   - читает остатки по складам (`warehouses_products_amount`) и город каждого склада;
   - определяет зону покупателя по городу, выбранному в шапке (`Tygh::$app['location']`);
   - передаёт это в `gm_dd_estimate()` из `lib/engine.php` и превращает даты в подписи
     («сегодня», «завтра», «9 октября, после 18:00», «11–12 октября»).
5. На оформлении заказа отдельный запрос `gm_delivery_date.checkout`: сервер берёт корзину и выбранный способ
   получения из сессии и возвращает срок по каждому товару, срок для всего заказа и товары, сгруппированные
   по сроку (`groups`: заголовок, подпись, фото, название, количество – функция `fn_gm_delivery_date_checkout_groups()`).
   Скрипт (`renderOrder()`) ставит в конец формы оформления карточки `.gm-dd-order` – по одной на каждый срок:
   «Можно забрать сегодня», «Привезём …», «Доставка СДЭК …», «Под заказ», а если срок не посчитан – «Товары в заказе».
   Стили карточек – секция 29 «Своего CSS». Хук `summary.post.tpl` (названия товаров в «Вашей корзине») удалён
   2026-10-07: товары теперь показывает карточка, ссылка в корзину – «Изменить заказ» в ней же.
   Там же скрипт по нажатию на строку города открывает окно выбора города из шапки (шаблон
   `geo_maps/customer_geolocation.tpl`); после выбора CS-Cart сам перезагружает оформление с новым городом.
   На телефоне строки города в шапке нет, поэтому окно открывается собственной скрытой ссылкой `#gm_co_city_opener`.
6. Блоки пересчитываются: после любой подгрузки содержимого (`ce.commoninit`), после смены города в шапке
   (`ce:geomap:location_set_after`), на оформлении – после любого запроса страницы (`ce.ajaxdone`).

Почему запросом, а не прямо в шаблоне: страницы и блоки магазина кэшируются, а срок зависит от времени и города.
Отдельный запрос всегда считает заново, поэтому в 20:01 покупатель видит уже «завтра». Сам расчёт занимает
около 1 мс на 60 товаров.

## Зоны покупателя

| Зона | Как определяется |
|---|---|
| `sev` | регион `SEV` или город «Севастополь» |
| `simf`, `yalta` | город «Симферополь» / «Ялта» |
| `crimea` | регион `KRY`, остальные города |
| `ru1`, `ru2`, `ru3` | пояса СДЭК по коду региона – списки в `fn_gm_delivery_date_ru_belt()` |
| `other` | страна не Россия или регион не определён – блок не показываем |

Склады: город берётся из карточки склада. Склад «Интернет-магазин» (id 50) считается севастопольским, но если
товар в Севастополе есть только на нём, порог самовывоза «сегодня» – 17:00, а не 20:00.

Товар без остатков на складах: в карточке – текст «под заказ», в корзине – «Под заказ», в каталоге – ничего
(там уже есть метка «Предзаказ»). Товар без складского учёта, но с общим остатком – блок не показываем.

## Что менять, если изменились условия

| Что изменилось | Где править |
|---|---|
| Пороги времени, дни рейсов, дни и часы курьера, праздники, сроки СДЭК | `engine.php` → `gm_dd_default_config()` |
| Логика маршрутов между городами | `engine.php` → `gm_dd_arrival()` |
| Регионы в поясах СДЭК | `func.php` → `fn_gm_delivery_date_ru_belt()` |
| Номера способов доставки (новый пункт выдачи, новый курьер) | `func.php` → `fn_gm_delivery_date_shipping_map()` |
| Номер склада «Интернет-магазин» | `func.php` → `fn_gm_delivery_date_internet_warehouse_ids()` |
| Тексты подписей («Пункт выдачи», «Под заказ») | `func.php` → `fn_gm_delivery_date_lines()`, `fn_gm_delivery_date_render()` |
| Куда на странице вставляется блок | `func.js` → `collect()` |
| Внешний вид | секция 28 в `CSS/goodmi-styles.css` и в «Своём CSS» |

После правки правил: дописать проверку в `tests.php`, запустить все проверки, скопировать `engine.php` в
`addon/…/lib/`, выложить. PHP-файлы начинают работать сразу; скрипт и шаблоны – после очистки кэша CS-Cart.

## Мультивитрина

Модуль установлен на всю систему (у CS-Cart один общий статус модуля), но работает только на витрине 2:

- скрипт подключается шаблоном с условием `$runtime.company_id == 2`;
- оба запроса возвращают пустой ответ на других витринах (`fn_gm_delivery_date_enabled()`);
- стили лежат только в «Своём CSS» GOODMi.

`func.php` при этом загружается на всех трёх витринах. Он только объявляет функции, но синтаксическая ошибка в
нём уронит все три магазина – перед выкладкой обязательно `php -l` на обеих версиях PHP сервера
(`/opt/php83/bin/php` и `php`).

Выключение модуля в админке («Модули») убирает блоки сразу и со всех страниц – это и есть откат.

## Проверка и диагностика

- **Правила:** `php tests.php` – должно быть «ошибок: 0».
- **На базе без установки:** скопировать папку модуля во временную папку сервера и запустить
  `integration-check.php <папка>` (читает остатки, показывает сроки для всех зон). Если модуль уже установлен,
  функции с теми же именами объявить второй раз нельзя – в копии заменить префикс `fn_gm_delivery_date_`.
- **На живом сайте:** в ответе запроса `gm_delivery_date.estimate` есть поле `gm_dd_zone` – какую зону модуль
  определил для покупателя. С параметром `gm_dd_debug=1` добавляется `gm_dd_location` – сам сохранённый адрес.
- **Телефон:** мобильную разметку отдаёт тема по типу устройства; в узком окне ПК её не видно. Смотреть
  настоящим телефоном или `curl` с мобильным User-Agent.

## Что обнаружили при запуске (чтобы не наступить второй раз)

- Повторный одинаковый запрос страница брала из своей памяти – в запрос добавлен параметр `_t` со временем.
- При смене города блоки не обновлялись без перезагрузки – добавлен пересчёт по событию смены локации.
- У мобильной карточки товара нет блока покупки `.ut2-pb__main-content-box` – добавлена отдельная точка вставки.
- На оформлении при одинаковом сроке у всех товаров дата выводилась дважды – теперь только общая строка.
- `geo_maps.set_location` без ключа `postal_code` молча не срабатывает (важно при тестах смены города).
