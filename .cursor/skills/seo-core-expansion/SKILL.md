# SEO Core Expansion — GOODMi

Расширяет ядро под **категорию в целом** (например «смартфоны Xiaomi», «повербанки», «роботы-пылесосы»), а не под одну модельную страницу. Не генерирует H1/title/description, не определяет наличие посадочной страницы под запрос — только семантику: находит, валидирует и отдаёт список новых релевантных запросов с реальной частотой. Что с ними делать (какая страница, нужна ли новая) — решает пользователь.

**Источник правил demand-filter, региона, broad/quoted, скрипт-разделения (кириллица/латиница) — `seo-meta-builder-v2`, разделы «Broad vs quoted» и Step 2b.** Не дублировать эти правила текстом — при расхождении в будущем приоритет у `seo-meta-builder-v2`, этот скилл обязан следовать её логике.

---

## Вход от пользователя

Один обязательный параметр:
1. **Корневой запрос / категория** — например «Xiaomi роботы-пылесосы», «повербанки», «Redmi Note»

Опционально: URL хаб-страницы категории — используется только как справочная метка в файле, не для проверки покрытия (это не задача скилла).

**Скилл не пишет в PixelPlus и не проверяет наличие страниц** — только читает PixelPlus для сверки на дубли (Step 4). Результат — файл-список (Step 5), который пользователь использует сам: смотрит, под какие запросы уже есть страница (трекнуть + при желании прогнать через `/user:seo-meta2`), под какие нет (создать), затем удаляет файл. При следующем запуске скилла свежее состояние PixelPlus (уже дополненное пользователем) снова читается в Step 4.

**Автономность — обязательна.** Если категория дана — выполнять весь workflow самостоятельно, без уточняющих вопросов.

## Workflow

### Step 1 — Wordstat-кластер (широкий: LSI, словоформы, употребления)

`wordstat_top(seed, num_phrases=60-80)` — шире, чем в meta-builder-v2 (там 30–40), т.к. категория, а не одна модель.

К результату вручную добавить (правила из `seo-meta-builder-v2` Step 2b):
- кириллица ↔ латиница для бренда/модели (таблица кириллических вариантов — в `seo-meta-builder-v2` Step 2b: Xiaomi/Сяоми, Redmi/Редми, POCO/Поко, Amazfit/Амазфит, Marshall/Маршалл, Oclean/Оклин, Laifen/Лайфен, Soocas/Сукас; JBL — не использовать)
- «купить» / «цена» коммерческие модификаторы
- гео: Севастополь, Симферополь, Ялта, Крым
- модельный ряд/линейки, встречающиеся в самих ассоциациях `wordstat_top` — включая то, что может оказаться новым для сайта; не фильтровать по «продаём ли мы это» — не входит в задачу скилла, частота и релевантность категории решают, попадает ли запрос в список, а не наличие товара

### Step 2 — Фильтр релевантности (обязателен, до проверки частоты — не тратить Wordstat-запросы на явный оффтоп)

Исключить только то, что **топически не о покупке этой категории товара**, независимо от каталога/наличия страниц (это решается на глаз по смыслу запроса, не через сверку с сайтом):

| Тип | Пример | Почему |
|---|---|---|
| Сервис/ремонт | «ремонт Xiaomi», «замена экрана Redmi» | Другая коммерческая вертикаль (услуги, не продажа устройств) |
| Аксессуары (для не-аксессуарной категории) | «чехол Xiaomi», «зарядка Redmi» | Другая товарная категория, не сама модель/линейка |
| Софт/прошивка, не про устройство | «прошивка Xiaomi», «MIUI скачать» | Не связано с покупкой техники |
| Конкурентные бренды / сторонние домены | «Xiaomi официальный сайт», «mi-shop.com» | Навигационный интент на чужой ресурс |
| Артефакты токенизации Wordstat | «xiaomi стоящий», «редми ноут стой» | Явно сломанный парсинг фразы, не реальный запрос |

**Не исключать** (это не задача скилла — решает пользователь): старые/новые модели вне видимого ассортимента, б/у, память/цвет и другие атрибуты, гео-варианты — всё, что топически про эту категорию, идёт дальше на проверку частоты.

**Оставить, но пометить отдельно «информационный»** (не то же самое, что коммерческий — трекать позицию бессмысленно, но список видеть полезно): сравнения моделей («Redmi Note 15 vs 14»), «как выбрать / какой выбрать».

### Step 3 — Региональная частота: broad И quoted (оба числа обязательны)

Правила broad/quoted — см. `seo-meta-builder-v2`, раздел «Broad vs quoted» (проверено эмпирически на этом же инструменте: `redmi note` broad/quoted разошлись ~700×, composite `xiaomi робот пылесос гарантия` — broad 10 / quoted 0). Кратко:

- **Broad** (без кавычек) — спрос на всю семью фраз. **Quoted** (в кавычках прямо в строке) — спрос на точную формулировку. Broad всегда ≥ quoted; если broad = 0, quoted не проверять (гарантированно 0).
- Для **относительных сравнений** (кириллица vs латиница, какой вариант написания выбрать) broad валиден — обе стороны измерены одинаково.
- Для **решения о спросе на конкретную формулировку** (включать ли в файл, тем более composite-USP-запросы) — решает **quoted**.

**Собирать оба числа одним батчем** — в список `phrases` для `wordstat_bulk` добавлять и обычную форму, и `"форму в кавычках"` для каждой кандидатной фразы. `wordstat_bulk(phrases=[кластер после Step 2, и та же кластер в кавычках], regions=[959, 146, 977])` — гео-каскад Севастополь+Симферополь+Крым (тот же, что в `seo-meta-builder-v2` Step 2b), батчами по 15–20 фраз (т.е. ~7–10 фраз-кандидатов на батч, т.к. каждая даёт 2 строки).

**Какое число на что влияет:**
- **Broad = 0** → исключить полностью, не выносить в файл (не тратить кавычки на заведомый ноль).
- **Broad > 0, quoted = 0 или предельно мало (1–3)** → включить в файл, но пометить как «спрос на семью фраз, не на точную формулировку» — не то же самое, что реальный трафик по этой строке. Не отправлять такой запрос напрямую в PixelPlus без понимания, что там на самом деле измеряется.
- **Quoted существенно > 0** → основной кандидат, именно quoted — число для сортировки и решений.

Composite-USP-запросы («+ гарантия», «+ доставка», «+ трейд-ин», «+ кредит», «+ самовывоз») тестировать только по отдельной просьбе — по умолчанию не тратить бюджет здесь, это задача `seo-meta-builder-v2` Step 3 при генерации конкретной страницы.

### Step 4 — Сверка с PixelPlus (обязательна, не пропускать)

**Сверка идёт по всему проекту, не по одной группе** — запрос мог быть добавлен раньше в другую группу.

1. `pixelplus_get_queries(project_id=63589)` **без `group_id`** — весь проект. Результат обычно превышает лимит вывода инструмента и сохраняется в файл — читать через `Bash`/Python (`json.load`), не построчным `Read`.
2. Дедуплицировать по `id` (один запрос может входить в несколько групп).
3. Сравнение с кластером Step 3 — **регистронезависимое, по нормализованному тексту** (`.strip().lower()`).
4. Совпадение → **уже трекается**, не включать в файл-список (кроме краткого перечисления для справки).

**Важно:** поле `frequency` в ответе `pixelplus_get_queries`, вероятнее всего, отражает **quoted**-частоту PixelPlus, а не «устаревшее» значение. Не полагаться на это поле для решений о спросе — использовать **только** для дедупликации по факту наличия запроса. Частота в файле — исключительно из Step 3 (`wordstat_bulk`, оба режима).

**Примечание про группы с одинаковым именем** (см. [[pixelplus-project]]): в проекте GOODMi уже встречались дубли имён групп («Телевизоры» — 2 группы с разным содержимым). Этот скилл только читает весь проект без фильтра по группе, поэтому дубли имён на сверку не влияют — они важны, только если пользователь позже сам решит отправить новые запросы через `pixelplus_add_queries` (вне scope этого скилла, см. `seo-meta-builder-v2` Step 6a).

### Step 5 — Файл со списком

**Папка:** `Расширение семантики/` (в корне репозитория; создать, если не существует).
**Имя файла:** `[slug-категории].md` — один файл на категорию, не по дате. При повторном запуске — перезаписать (`Write`). Файл одноразовый рабочий: пользователь читает, решает по каждому запросу (страница есть → трекнуть/доработать через `/user:seo-meta2`; страницы нет → создать), затем удаляет файл сам.

**Формат:**

```markdown
# Расширение ядра: [Категория]
Обновлено: [ГГГГ-ММ-ДД]

## Пояснения

[Свободный текст, самодостаточный (пользователь не видел чат): сколько проверено кластерных запросов, сколько отсеялось (нулевая частота / оффтоп-фильтр Step 2), заметные находки (перевес кириллицы/латиницы, неожиданно частотный вариант, и т.п.), любые ограничения проверки.]

## Новые запросы (коммерческие/навигационные — сортировка по quoted)

| Запрос | Broad (регион) | Quoted (регион) | Примечание |
|---|---|---|---|
| [запрос] | N | M | [пусто, если quoted существенно > 0; иначе «спрос на семью фраз, точная формулировка почти не ищется»] |

## Информационные (сравнения, «как выбрать» — трекать не нужно, но видеть полезно)

| Запрос | Broad (регион) | Quoted (регион) |
|---|---|---|
| [запрос] | N | M |

## Исключено как оффтоп для категории

[Кратко, по типам: «сервис/ремонт: N запросов», «аксессуары: N запросов» и т.д. — не расписывать каждый запрос.]

## Уже трекается в PixelPlus (для справки)

[запрос1] · [запрос2] · ...
```

Ничего в PixelPlus не отправлять, страницы не создавать, наличие URL не проверять — это работа пользователя по этому файлу, не скилла.

## Разграничение с seo-meta-builder-v2

| | seo-core-expansion | seo-meta-builder-v2 |
|---|---|---|
| Вход | Категория (без URL) | Одна страница/модель |
| Выход | Список новых релевантных запросов с частотой | H1 + title + description + JSON-LD + своё ядро |
| Проверка наличия страницы | Нет — не задача скилла | Не применимо (страница уже задана) |
| Wordstat-кластер | Шире (60–80), без SERP-анализа конкурентов | Точнее под одну страницу (30–40) + SERP Gap Analysis |
| PixelPlus-сверка | Обязательный отдельный шаг (Step 4) | Только отправка новых (Step 6a), сверки на дубли нет |
| Когда использовать | Периодически, для категории целиком | При создании/обновлении конкретной страницы |

Если пользователь просит и мета-теги, и расширение ядра для одной конкретной модельной страницы — это `seo-meta-builder-v2`, не этот скилл.
