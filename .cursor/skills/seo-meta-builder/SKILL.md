# SEO Meta Builder — GOODMi

Generates H1, title, and meta description for **goodmi.ru** pages.

## Приоритет трафика: Яндекс первый

Данные аналитики GOODMi:
- **Яндекс**: 58% органического трафика, конверсия в заказы в **2 раза выше**, чем с Google
- **Google**: 41% органического трафика
- **Расчётный вес выручки**: Яндекс ≈ **74%**, Google ≈ **26%**

**Принцип работы скила:** оптимизируем под Яндекс в первую очередь, обеспечиваем соответствие Google во вторую. Жёстких требований к формату нет — главное получить максимальный трафик и позиции, не нарушая технические требования поисковых систем.

## Geo-стратегия GOODMi

| Уровень | Гео | Где использовать |
|---|---|---|
| Региональный | **Крым** | title (основной геотаргет), description, JSON-LD areaServed |
| Главный город | **Севастополь** | description (главный магазин), SERP-анализ |
| Города присутствия | **Симферополь, Ялта** | description (USP самовывоза) |

**Принцип:** «Крым» в title = максимальный региональный охват. Конкретные города усиливают локальный сигнал в description. В H1 категорий гео не указывается — магазин обслуживает всю Россию через СДЭК.

## Workflow (execute in order)

### Step 1 — Parse the request

Extract from the user's message:
- **Page type**: конкретная модель / серия / топовая категория / аксессуары / сервис
- **Product name / category** (e.g., Xiaomi 15 Pro, Redmi Note 15 Pro, планшеты, ноутбуки)
- **Keyword data**: если пользователь предоставил список ключей с частотностью/значимостью — использовать как основу анализа
- **Quantity**: single page or batch

Если keyword data не предоставлена — выполнить Step 2 (SERP research).
Если keyword data предоставлена — перейти сразу к Step 2b (оценка ключей).

For batch requests — process all items in a single output table.

---

### Step 2 — SERP research

Выполнять когда: keyword data не предоставлена пользователем.

Run **4 WebSearch queries in parallel**:

1. `"купить [Категория/Модель] Севастополь"` — title-паттерны главного города
2. `"купить [Категория/Модель] Симферополь"` — паттерны второго города
3. `"купить [Категория/Модель] Крым"` — региональные паттерны конкурентов
4. `"[Кириллический вариант] купить"` — реальная частотность кириллических написаний

**Цель:** выявить незанятые углы в title конкурентов, сильные CTR-паттерны, разницу конкуренции по гео. Выбирать паттерн с наименьшей конкуренцией и максимальным охватом.

---

### Step 2b — Анализ ключевых слов (traffic scoring)

**Расчёт эффективного веса каждого ключа для GOODMi:**

```
Эффективный вес = (Яндекс-значимость × 0.74) + (Google-значимость × 0.26)
```

Если источник не разделён по системам — использовать значимость как есть.

**Классификация ключей по порогу:**

| Значимость | Решение |
|---|---|
| ≥ 35 | **Кандидат в title** — высокочастотный запрос, точное вхождение в title даёт реальный прирост трафика Яндекса |
| 15–34 | **Кандидат в description** — семантический хвост, Google покроет через семантику, Яндекс — через расширенный сниппет |
| < 15 | Пропустить — не окупает место в теге |

**Кириллические варианты брендов:**

Кириллика в title — это инструмент Яндекс-матчинга, не ошибка. Решение принимается по порогу:

- Значимость ≥ 35 → **интегрировать в title** (предпочтительно естественно: `Redmi Note 14 (Редми Нота)`)
- Значимость 15–34 → description (расширенный хвост за ~155 симв.)
- Значимость < 15 → не использовать

| Бренд | Кириллический вариант |
|---|---|
| Xiaomi | Сяоми |
| Redmi | Редми |
| POCO | Поко |
| Amazfit | Амазфит |
| Marshall | Маршалл |
| Oclean | Оклин |
| Laifen | Лайфен |
| Soocas | Сукас |
| JBL | не использовать |

### Step 3 — Генерация мета-тегов (traffic-first)

**Цель не шаблон, а покрытие.** Для каждой страницы нужно максимально охватить высоковесовые ключи в рамках технических ограничений поисковых систем.

#### H1

H1 — навигационный заголовок: пользователь уже на сайте, коммерческие запросы ему не нужны.

- **Категория / серия**: `[Категория] [Бренд]`, без «Купить», без гео, 15–45 симв.
- **Конкретная модель**: `[Тип товара] [Модель]`, без «Купить», без гео, 15–45 симв.
- Весь коммерческий сигнал переносится в title и description.
- Запрещено: «официальный», «авторизованный».

#### title

**Технические ограничения (жёсткие):**
- Google обрезает после ~65 симв. / 580px
- Yandex показывает до ~70 симв. без обрезки
- Нет keyword stuffing (неестественного повтора ключей)
- Нет caps, нет `!`, нет цен в ₽
- `GOODMi` всегда последним после `|`

**Процесс генерации title (по шагам):**

1. Взять ключ с максимальным эффективным весом → это основа title
2. Добавить коммерческий сигнал: «купить», «цена», «гарантия» (выбрать по длине)
3. Добавить гео: «в Крыму» (региональный охват)
4. Оценить кириллические варианты: если значимость ≥ 35 → добавить естественно в скобках или через `/`
5. Добавить `| GOODMi`
6. Составить **2–3 варианта title** с разным набором ключей
7. Для каждого варианта посчитать покрытие ключей и длину
8. Выбрать вариант с максимальным покрытием, не превышающий 65 симв. (предпочтительно) или 70 симв. (если Яндекс-выгода оправдывает)

**Правило первого слова в title:**
- Продукт первым → читается моментально в SERP: `Redmi Note 14 — купить...`
- «Купить» в начале title — только для страниц конкретных моделей (намерение покупки очевидно)
- Для категорий и серий: продукт первым, «купить» внутри

#### meta description

**Технические ограничения:**
- Google Desktop: ~155 симв. видимый сниппет
- Яндекс расширенный сниппет: до 300+ симв.
- Оптимальная длина для GOODMi: **180–270 симв.** (покрывает оба формата)

**Структура:**
```
[Ключевой запрос] в GOODMi — [USP-1], [USP-2], [USP-3]. [CTA].    ← до ~155 симв.
[Модельный ряд / кириллические хвосты / E-E-A-T].                  ← 155–270 симв.
```

- Первое предложение = прямой ответ на коммерческий запрос (GEO/AEO — AI цитирует дословно)
- Ключи, не попавшие в title → интегрировать в description естественно
- Кириллические варианты со значимостью 15–34 → добавить в расширенный хвост (после ~155 симв.)
- Доставку и самовывоз указывать вместе: «доставка СДЭК, самовывоз в Крыму»
- CTA: «Заказывайте онлайн» / «Оформите заказ» / «Выбирайте в каталоге»

**Approved USPs** (использовать дословно или с адаптацией):
- «гарантия 1 год»
- «доставка СДЭК» / «доставка по России через СДЭК»
- «самовывоз в Крыму» / «самовывоз в Севастополе, Симферополе, Ялте» / «6 точек в Крыму»
- «трейд-ин»
- «кредит» / «покупка в кредит»
- «фирменный магазин техники Xiaomi»
- «с 2016 года» / «более 10 лет»
- «бонусная программа GOODMi»

> Запрещено везде: «рассрочка», «официальный», «авторизованный», эмодзи, цены в ₽, `!`

**Многобрендовые категории:**
- H1: `[Тип товара] Xiaomi, [Бренд2]` — не более 2 брендов-партнёров
- title: `[Тип товара] [Бренды] — купить в Крыму | GOODMi`
- Остальные бренды → description

### Step 4 — Проверка перед выводом

**Таблица покрытия ключей:**

| Ключ | Значимость | Где покрыт | Выгода |
|---|---|---|---|
| [ключ] | N | title / description / не покрыт | Яндекс / Google / — |

**Проверка соответствия требованиям поисковых систем:**

| Параметр | Требование | Статус |
|---|---|---|
| title длина | ≤ 65 симв. (Google) / ≤ 70 симв. (Яндекс) | ✓/✗ |
| description длина | 180–270 симв. | ✓/✗ |
| Keyword stuffing | Отсутствует | ✓/✗ |
| H1 ≠ title дословно | Разные тексты | ✓/✗ |
| Гео в H1 ≠ гео в title | Разные слова | ✓/✗ |
| GOODMi в title | Последнее после `\|` | ✓/✗ |
| Запрещённые слова | рассрочка / официальный / авторизованный | ✓/✗ |
| CTA в description | Присутствует | ✓/✗ |
| 2+ USP в description | Присутствуют | ✓/✗ |

### Step 5 — Output format

**Single page:**

```
H1:          [текст]    ([N] симв.)
title:       [текст]    ([N] симв.)
description: [текст]    ([N] симв.)
```

Затем — **таблица покрытия ключей** (из Step 4) + короткий комментарий: какой вариант title выбран и почему, что покрывает description.

**Batch (несколько страниц):**

| Страница | H1 | title | Дл. title | description | Дл. desc |
|---|---|---|---|---|---|
| [страница] | … | … | N | … | N |

После таблицы — комментарий о паттернах и покрытии.

---

### Step 6 — Семантическое ядро (запросы для отслеживания)

Выводить всегда после Step 5 — для каждой страницы, включая batch.

**Принцип формирования:** запросы выводятся на основе проанализированного продукта/категории и охватывают те же ключи, что легли в основу title и description. Не изобретать новые запросы — только то, что подтверждено SERP-анализом или keyword data.

**Категории запросов (включать при наличии смысла для страницы):**

| Категория | Примеры |
|---|---|
| Коммерческие (основа) | `купить [Продукт]`, `[Продукт] купить`, `[Продукт] цена` |
| Категорийные | `ноутбуки [Серия]`, `[Тип товара] [Бренд]` |
| Гео (региональный) | `[Продукт] Крым`, `купить [Продукт] в Крыму` |
| Гео (города) | `[Продукт] Севастополь`, `[Продукт] Симферополь` |
| Годовые уточнители | `[Продукт] 2024`, `[Продукт] 2025` — только если страница включает несколько поколений |
| Подсерии | `[Продукт] Pro`, `[Продукт] Lite` — только если присутствуют на странице |
| Кириллические | `[Кириллика] купить`, `[Кириллика] цена` — только если значимость ≥ 15 |
| Широкие категорийные | `[тип товара] [бренд] [диагональ/размер]` — 1–2 запроса для оценки видимости |

**Формат вывода** — всегда код-блок, одна строка = один запрос:

~~~
[запрос 1]
[запрос 2]
...
~~~

Заголовок блока: `**Запросы для семантического ядра:**`

Batch: отдельный блок для каждой страницы с заголовком-названием страницы.

## E-E-A-T mapping

| Сигнал | Где ставить | Фраза |
|---|---|---|
| Experience | description (конец) | «фирменный магазин Xiaomi с 2016 года» |
| Expertise | description (середина) | «фирменный магазин техники Xiaomi» |
| Authoritativeness | description | «крупнейший магазин Xiaomi в Крыму» / «5.0 / 500+ отзывов» |
| Trustworthiness | description (USP) | «гарантия 1 год», «трейд-ин», «доставка СДЭК» |

Не используй более одного E-E-A-T сигнала одного типа — охватывай разные стороны.
