## Нейроответы — стратегия v2

### Когда коммерческая страница попадает в нейроответ

AI-поисковики (Яндекс Нейро, Google AI Overviews, ChatGPT Search) генерируют ответы **преимущественно на информационные запросы**. Это означает:

| Тип запроса | Шанс нейроответа | Примеры |
|---|---|---|
| Транзакционный | Очень низкий | «купить смартфон Xiaomi Крым», «цена Redmi Note» |
| Коммерческий с условием | Низкий | «гарантия на Xiaomi в GOODMi», «трейд-ин смартфон Севастополь» |
| Сравнительный / выборочный | **Средний** | «чем Xiaomi 15 отличается от Redmi Note», «какой смартфон Xiaomi лучше» |
| Информационный про продукт | **Высокий** | «как выбрать планшет Xiaomi», «что важно в смартфоне до 30000» |
| Информационный про магазин | **Высокий** | «какая гарантия на технику Xiaomi», «как работает трейд-ин» |

**Вывод:** коммерческие страницы категорий GOODMi цитируются в нейроответах через:
1. **FAQ-блок** — прямые ответы на информационные вопросы покупателей
2. **`.gm-intro-text`** — самодостаточные абзацы с конкретными фактами
3. **`WebPage.description`** в JSON-LD — первый источник для Яндекс Нейро и ChatGPT Search
4. **Блог-статьи** — основной канал для информационных запросов (вне scope этого скила)

**Практическое правило:** оптимизация мета-тегов влияет на нейроответы косвенно (через `WebPage.description`). Основная работа по нейроответам — в контенте страницы (shop-page-builder-v2).

### Флаг нейроответа

Если пользователь явно упоминает нейроответы, AI Overviews, Яндекс Нейро или хочет «цитироваться» — активировать **информационный маршрут** в Step 1 и Step 2d.

## Workflow (execute in order)

### Step 1 — Parse the request

Extract from the user's message:
- **Page type**: конкретная модель / серия / топовая категория / аксессуары / сервис-услуга
  - **Исключение — пагинация / фильтры** (`?page=2`, `?features_hash=...`): скилл не генерирует мета-теги для этих URL.
- **Product name / category** (e.g., Xiaomi 15 Pro, Redmi Note, планшеты, ремонт)
- **Keyword data**: если пользователь предоставил список ключей с частотностью/значимостью
- **Quantity**: single page or batch
- **[v2] Флаг нейроответа**: упомянуты ли нейроответы, AI Overviews, «цитируемость» — если да, активировать Step 2d
- **[v2] Мультибренд**: если в названии категории, URL или описании пользователя упомянуто 2+ бренда (например «Xiaomi, Dreame, Roborock» или «роботы-пылесосы» с несколькими брендами в ассортименте) — зафиксировать список **вторичных брендов** (все кроме Xiaomi), активировать **Step 2e**. Xiaomi всегда основной бренд для SERP-запросов.

**Маршрут выполнения:**

```
keyword data НЕ предоставлена → Step 2 (3 запроса) → [Step 2e если мультибренд] → [Step 2d если флаг] → Step 2b → Step 2c → Step 3
keyword data предоставлена    → Step 2-mini (3 запроса) → [Step 2e если мультибренд] → [Step 2d если флаг] → Step 2b → Step 2c → Step 3
```

**Step 2c (Gap Analysis) выполняется всегда.** При пропущенном основном Step 2 — выполнить **Step 2-mini**: 2 WebSearch параллельно (обязательные):
1. `"купить [Категория/Модель] Крым"` — поиск реальных конкурентов
2. `"[Категория/Модель] Севастополь"` — региональные конкуренты

**Опциональный запрос №3** — только если планируется HTML-блок (shop-page-builder):
3. `"как выбрать [Категория/Модель] Xiaomi"` — FAQ-семена для shop-page-builder

После Step 2-mini — также выписать домены из топ-10 по каждому запросу и проверить наличие приоритетных конкурентов GOODMi (полный список — в Step 2). Найденных пометить **★** для Step 2c.

**Batch-режим — стратегия SERP-запросов:**
- **2–4 страницы**: запустить WebSearch для каждой страницы параллельно (N×3 одновременно).
- **5+ страниц**: группировать похожие категории.

### [v2] Step 2d — Информационный SERP (для нейроответов)

**Когда выполнять:** активирован флаг нейроответа из Step 1 ИЛИ пользователь планирует HTML-блок (тогда данные передаются в shop-page-builder-v2).

Run **3 WebSearch queries** (параллельно с основным Step 2 или после него):

1. `"как выбрать [Категория] Xiaomi"` — информационные вопросы покупателей; семена для FAQ
2. `"[Категория] Xiaomi [год] какой лучше"` — сравнительные запросы; чаще всего триггерят нейроответ
3. `"чем отличается [Модель A] от [Модель B] Xiaomi"` — конкретное сравнение; прямой кандидат в нейроответ

**Цель Step 2d:** найти информационные запросы, по которым GOODMi МОЖЕТ попасть в нейроответ. Коммерческие страницы конкурируют с агрегаторами по транзакционным запросам — они не конкурируют по информационным.

**После получения результатов — зафиксировать:**
- Какие информационные вопросы присутствуют в поиске
- Кто уже цитируется в нейроответах (если видно в SERP-сниппетах)
- Какие вопросы не закрыты конкурентами → приоритет для FAQ-контента

**Вывести перед Step 3 блок «Потенциал нейроответов»:**

```
## Потенциал нейроответов: [Категория]

### Информационные запросы (Step 2d):
- «[запрос]» — [кто цитируется / не закрыт]
- «[запрос]» — [кто цитируется / не закрыт]

### Рекомендации:
→ FAQ: включить вопрос «[вопрос из Step 2d]» — прямой кандидат в нейроответ
→ WebPage.description: начать с прямого ответа на «[запрос]»
→ Блог: тема «[расширенный информационный запрос]» — вне scope мета-тегов
```

### [v2] Step 2e — Мультибренд SERP (обязателен при наличии вторичных брендов)

**Когда выполнять:** Step 1 зафиксировал 2+ бренда на странице. Выполнять параллельно со Step 2d (или сразу после Step 2, если Step 2d не активирован).

**Для каждого вторичного бренда** (не Xiaomi) — запустить **2 WebSearch параллельно**:

1. `"купить [Бренд] [категория] Севастополь"` — есть ли GOODMi в топ-10? Кто конкурирует?
2. `"[Бренд] официальный магазин Россия [категория]"` — есть ли у бренда свой интернет-магазин?

При 2 вторичных брендах (например Dreame + Roborock) — **4 запроса параллельно**.

**После получения результатов — для каждого бренда заполнить таблицу:**

```
## Мультибренд SERP: [Категория]

| Бренд | Офиц. магазин в топ-10 | Агрегаторов | GOODMi в топ-10 | Флаг |
|---|---|---|---|---|
| [Бренд] | да / нет → [домен] | N | да / нет | 🎯 / 👁 / — |
```

**Правила присвоения флага:**

| Условие | Флаг | Действие |
|---|---|---|
| Есть офиц. магазин бренда в топ-10 | **—** | Брендовый запрос нереалистичен. Бренд → только в description как ассортиментный сигнал. |
| Нет офиц. магазина + 0–1 агрегатор | **🎯** | GOODMi может конкурировать. Бренд → кандидат в title. |
| Нет офиц. магазина + 2–3 агрегатора | **👁** | Сложно, но мониторить. Бренд → description. |
| Нет офиц. магазина + 4+ агрегатора | **—** | Не включать в title. |

**Стратегические выводы Step 2e передать в Step 3:**

- Бренд с флагом **—** → упомянуть в description и H1 (как ассортиментный факт), **не включать в title**
- Бренд с флагом **🎯** → кандидат в title (Вариант с мультибрендом)
- Бренд с флагом **👁** → включить в description, в title опционально

```

```

|---|---|

### Step 3 — Генерация мета-тегов

#### Правила по типу страницы

| Тип страницы | H1 — формат | Гео в H1 | «Купить» в title | Трейд-ин в USP |
|---|---|---|---|---|
| Топовая категория | `[Тип товара] Xiaomi` | Нет | Внутри title | Да |
| Серия моделей | `[Тип товара] [Серия]` | Нет | Внутри title | Да |
| Конкретная модель | `[Тип товара] [Полное название модели]` | Нет | Первое слово в title | Да |
| Аксессуары | `[Тип аксессуара] Xiaomi` | Нет | Внутри title | Нет |
| Сервис / услуга | `[Услуга] Xiaomi в [Город]` | **Да — обязательно** | Не использовать | Нет |

#### H1 — правила

- Диапазон: **15–45 симв.**
- Порядок слов: тип устройства → бренд → серия/модель
- Запрещено: «Купить», «официальный», «авторизованный»
- Полное официальное название, без кириллики
- Для сервисных страниц: услуга + бренд + город

#### title — варианты по стратегическим осям

**Технические ограничения:**
- Google обрезает после ~65 симв. / 580px
- Yandex показывает до ~70 симв.
- Нет keyword stuffing, нет caps, нет `!`, нет цен в ₽
- `GOODMi` всегда последним после `|`

**Три стратегические оси:**

| Ось | Что варьировать |
|---|---|
| **А — кириллика** | с/без кириллического варианта бренда |
| **Б — коммерческий сигнал** | «купить» vs «цена» vs «гарантия» |
| **В — длина/гео** | «в Крыму» vs «в Севастополе» |

Построить **2–3 варианта**, показать пользователю все, рекомендовать один.

#### meta description

**Технические ограничения:**
- Google Desktop: ~155 симв. видимый сниппет
- Яндекс расширенный сниппет: до 300+ симв.
- Оптимальная длина: **180–270 симв.**

**AEO-паттерн первого предложения:**

Структура: `[Продукт/Категория] в GOODMi — [прямой ответ на коммерческий запрос]`

AI-системы цитируют предложения, которые:
- Начинаются с объекта запроса (не с «Мы», не с «GOODMi»)
- Содержат прямой ответ в первых 10 словах
- Включают гео-сигнал (Крым / Севастополь)
- Содержат конкретный факт (число лет, число точек, срок доставки)

❌ Слабо: «GOODMi предлагает смартфоны Xiaomi с доставкой по России.»
✅ Сильно: «Смартфоны Xiaomi в GOODMi — гарантия 1 год, доставка СДЭК, самовывоз в 6 точках Крыма.»

**Структура description — фиксированный порядок:**

*Для товарных страниц:*
```
[AEO-первое предложение: продукт + USP-1, USP-2, USP-3 + CTA]     ← до ~155 симв.
[Модельный ряд / ключевые характеристики продукта]                  ← приоритет в хвосте
[Кириллические хвосты — если значимость 15–34]
[E-E-A-T: Experience («с 2016 года») → Authoritativeness]           ← в конце хвоста
```

*Для сервисных страниц:*
```
[AEO-первое предложение: услуга + город + главный USP сервиса]
[Перечень работ / услуг]
[Условия сервиса: запчасти, срок, запись]
[E-E-A-T: опыт мастеров, количество точек]
```

**E-E-A-T в description — приоритет при нехватке места:**

| Приоритет | Сигнал | Фраза | Условие |
|---|---|---|---|
| 1 — обязательно | Trustworthiness | «гарантия 1 год», «трейд-ин», «доставка СДЭК» | Всегда, первые 155 симв. |
| 2 — обязательно | Expertise | «фирменный магазин техники Xiaomi» | Всегда |
| 3 — при длине > 180 | Experience | «с 2016 года» / «более 9 лет» | В хвосте |
| 4 — при длине > 220 | Authoritativeness | «крупнейший магазин Xiaomi в Крыму» | Только если есть место |

#### [v2] JSON-LD description — строгие правила для нейроответов

**`WebPage.description`** — главный источник для Яндекс Нейро и ChatGPT Search:

**Обязательные правила (v2):**
- **НЕ начинать** с «GOODMi», «Мы», «В нашем магазине» — начинать с объекта запроса
- Должно быть **одно полное предложение**, не обрезанное на полуслове
- Должен содержать **прямой ответ** на главный транзакционный запрос страницы
- Должен содержать **минимум одно конкретное число**: «6 точек», «с 2016 года», «365 дней»
- Длина: **120–180 симв.** — одно законченное предложение легче цитировать, чем многострочный блок

✅ Правильно: «Смартфоны Xiaomi в GOODMi — гарантия 1 год, доставка СДЭК, самовывоз в 6 точках Крыма, с 2016 года.»
❌ Неправильно: «GOODMi — фирменный магазин Xiaomi в Крыму. Здесь вы найдёте широкий выбор смартфонов.»

**`LocalBusiness.description`** — 2–3 предложения: специализация + гео + главный USP. Не повторять `WebPage.description` дословно.

Пример: «GOODMi — фирменный магазин техники Xiaomi в Крыму с 2016 года. Самовывоз в 6 точках: 4 в Севастополе, Симферополь, Ялта. Доставка СДЭК по всей России, трейд-ин, покупка в кредит.»

**[v2] `LocalBusiness.sameAs` — обязательно:**

```json
"sameAs": [
  "https://yandex.ru/maps/org/goodmi/81345582117/"
]
```

Зачем: Яндекс Нейро и ChatGPT Search используют `sameAs` для подтверждения авторитетности организации. Ссылка на верифицированную карточку Яндекс Карт — прямой сигнал доверия.
