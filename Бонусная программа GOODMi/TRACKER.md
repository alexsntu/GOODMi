## Вводные данные
- **Архитектура: отдельный сервис, не привязываемся к CS-Cart.** (пользователь, 2026-08-11). Т.е. логика начисления/списания кешбека живёт вне CS-Cart-аддонов, самостоятельным сервисом.
- **Деплой: свой сервер** (не CS-Cart, не SaaS). (пользователь, 2026-08-11)
- **Стек: возможно Python** — пока не окончательно, «возможно» (пользователь, 2026-08-11)
- **Синхронизация с двумя внешними системами:** (1) сайт (goodmi.ru / CS-Cart) и (2) программа учёта — **МойСклад** (МойСклад.ру, у него есть открытое JSON API). (пользователь, 2026-08-11)
- **Источник истины по покупкам — МойСклад.** Именно там фиксируются покупки, за которые начисляется или списывается кешбек (не заказы CS-Cart напрямую). (пользователь, 2026-08-11)
- **Что нужно хранить/показывать по каждому покупателю:** все операции; бонусы; покупки, за которые начислили (бонусы); доступные бонусы (текущий баланс). (пользователь, 2026-08-11)
- **Личный кабинет покупателя (баланс, бонусы к начислению и т.п.) — на отдельном ресурсе**, не на самом сайте goodmi.ru / не в ЛК CS-Cart. Т.е. у кешбек-сервиса свой отдельный веб-интерфейс для покупателя. (пользователь, 2026-08-11)
- **Референс-макет ЛК покупателя** — прислан скриншот, сохранён в `reference-user-cabinet-mockup.png` в этой папке. Элементы на макете:
  - Блок «Доступно сейчас»: N бонусов = N ₽ скидки на покупки; кнопки «Как потратить» и «История».
  - Блок «Скоро сгорят»: N бонусов.
  - Блок «Ожидают начисления»: N бонусов, подпись «после получения заказов».
  - Блок «Ваш уровень» (тиры, напр. Серебряный) с прогресс-баром «Накоплено X бонусов из Y» до следующего уровня.
  - Таблица операций с табами: Все / Начисления / Списания / Скоро начислят + Фильтры; колонки: Операция, Описание, Дата, Бонусы.
  - Блок «Срок действия бонусов»: «Бонусы действуют 365 дней с даты начисления» + ссылка «Подробнее».
  - Блок «Бонусы, которые сгорят» — список бонусов с ближайшим сроком сгорания.
  - **Важно:** это референс/пример «как может выглядеть», не готовое ТЗ — сам факт наличия тиров/сроков сгорания/статуса «ожидают начисления» ещё не подтверждён как обязательное правило для GOODMi, уточнить при финализации.

## Открытые вопросы
- Как именно кешбек-сервис получает данные из МойСклад: вебхуки МойСклад, периодический опрос API, что считается «покупкой» (продажа/отгрузка/заказ)?
- Раз ЛК покупателя (баланс/бонусы) будет на отдельном ресурсе, а не на сайте — зачем и как тогда используется сайт (CS-Cart) в синхронизации вообще? Что именно сайт отдаёт/получает от кешбек-сервиса?
- Оффлайн-покупки (в магазинах Севастополь/Симферополь/Ялта) тоже фиксируются в МойСклад и тоже участвуют в начислении кешбека?
- Направление синхронизации с сайтом: только чтение баланса, или сайт тоже пишет в кешбек-сервис (например при онлайн-оплате бонусами)?
- Процент/правила начисления кешбека (фикс % от суммы? по категориям? по акциям?), ограничения, срок сгорания бонусов.
- Как кешбек списывается/используется при следующей покупке — правила списания, максимальная доля оплаты бонусами.
- Привязка к аккаунту: где живёт личный кабинет/авторизация покупателя — на стороне нового сервиса или используется существующий ЛК CS-Cart?
- Нужна ли интеграция с GOODMi:club (Wallet-картой) для отображения баланса, или кешбек живёт отдельно?
- Окончательный стек (язык фикс, БД, где именно на сервере — тот же VPS что и сайт, или отдельный)?

## Материалы для ориентира (не решение, справочно)
Посмотрел, что есть на GitHub по теме loyalty/cashback — для общего кругозора, архитектурные решения принимать будем свои, под вводные пользователя:
- Open Loyalty — API-first loyalty engine (баллы, кошельки, рефералки, бейджи), близкий по духу к «отдельному сервису».
- thirtybees/loyalty — модуль лояльности для другой e-commerce платформы (thirty bees), для сравнения с встроенным подходом.
- CS-Cart имеет собственный нативный аддон «Reward Points» (баллы за покупки, списание на следующие) — но т.к. мы не привязываемся к CS-Cart, это не наш путь, только справочно как пример правил начисления/списания.
- Типовой паттерн в open-source примерах: баллы/кешбек считаются в отдельном микросервисе, привязка к account_id, статусы/тиры (bronze/silver/gold), API для начисления и списания.
