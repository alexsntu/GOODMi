# Массовое списание бонусов в БонусПлюс

Инструмент для разовой (по запросу пользователя) корректировки бонусных балансов клиентов в стороннем loyalty-сервисе [bonusplus.pro](https://bonusplus.pro/) — например, отмена ошибочно начисленных бонусов у пачки клиентов.

Скрипты лежат в `bonusplus-integration/scripts/`, читают ключ API из `bonusplus-integration/.env` (`BONUSPLUS_API_KEY`). Если файла нет — попроси пользователя дать ключ и создай `.env` по образцу `.env.example` (см. `bonusplus-integration/README.md`).

**У этого же процесса есть self-service UI** — раздел «Бонусы» на маркетинг-портале (`marketing-portal/src/routes/bonuses.js` + `bonuses.ejs`/`bonus-batch.ejs`/`bonuses-log.ejs`, таблицы `bonus_batches`/`bonus_batch_items`/`bonus_batch_log` в `db.js`): вставить список → превью → «Списать по плану» → (если нужно) два списка на активацию → «Бонусы активированы — списать по списку» → журнал операций на `/bonuses/log`. Та же логика (min(запрошено, баланс), тот же запрет на `transactionType:30`), просто пользователь может прогнать это сам без сессии с ассистентом. Используй этот скилл, когда пользователь явно просит именно тебя списать бонусы в чате/сессии; если речь про сам портал — правь `marketing-portal/`, а не эти скрипты.

**Это правки по живым клиентским счетам. Никогда не выполняй списание без явного подтверждения пользователем превью.**

## Шаг 0 — вводные

Спроси (если не даны сразу): список `телефон  сумма` (по одному на строку — так же, как пользователь присылает обычно), и правило на случай нехватки баланса (по умолчанию, если не оговорено иначе: списываем до 0, не в минус).

Сохрани список в `bonusplus-integration/lists/deduct_<YYYY-MM-DD>.txt` (папка `lists/` в `.gitignore` — реальные телефоны/имена в git не попадают, не убирай это правило).

## Шаг 1 — превью

```
python bonusplus-integration/scripts/deduct_preview.py bonusplus-integration/lists/deduct_<дата>.txt
```

Скрипт сам:
- суммирует дублирующиеся телефоны в списке (если есть) — **обязательно покажи это пользователю и уточни, что суммирование ожидаемо**, прежде чем продолжать;
- запрашивает у БонусПлюс текущий баланс каждого клиента;
- считает `actual_deduct = min(запрошено, текущий_баланс)` (списание до 0, не в минус);
- сохраняет план в `<файл>_plan.json` (тоже в `.gitignore`);
- печатает клиентов, где активного баланса не хватает И есть `pending` (`notActiveBonuses` > 0) — это важно для шага 3.

Покажи пользователю итоговую таблицу (телефон/имя/баланс/спишем/останется) и суммы (итого запрошено vs итого реально спишется). **Дождись явного подтверждения** — только после него переходи к шагу 2.

## Шаг 2 — списание

```
python bonusplus-integration/scripts/deduct_execute.py bonusplus-integration/lists/deduct_<дата>_plan.json
```

Списывает `actual_deduct` у каждого клиента через `PATCH /customer/{phone}/balance` (`amount` — отрицательная дельта). Клиентов с `actual_deduct == 0` пропускает. Выведи пользователю итог: сколько списано, сколько пропущено, ошибки (если есть).

## Шаг 3 — если есть недосписанные из-за pending-бонусов

Если на шаге 1 были клиенты с нехваткой баланса **и** ненулевым `pending` — у БонусПлюс есть отдельный бакет «ожидающие/неактивные бонусы» (`notActiveBonuses`), который не участвует в списании через API до момента активации.

### ⚠️ Критично: как НЕ активировать pending-бонусы

**Не используй `PATCH /customer/{phone}/balance` с `transactionType: 30` (`Credit_ActivateBonuses`) для перевода pending → active.** Это не перевод, а отдельное начисление: сумма добавляется к активному балансу, а `notActiveBonuses` **не уменьшается** — итог двойное начисление клиенту. Проверено эмпирически 2026-09-02 (на реальном клиенте, пришлось откатывать вручную обратной проводкой). В документированном REST API способа активировать pending-бонусы **нет вообще**.

### Как правильно

Активация возможна только вручную, через веб-админку БонусПлюс (`bonusplus.pro/lk_new/`) — это делает пользователь сам, не ты (вход по логину/паролю — ты не имеешь права вводить пароли, см. общие правила безопасности):

1. Покажи пользователю список телефонов, у которых нужна активация (из вывода шага 1, строки с пометкой `ВНИМАНИЕ`).
2. Попроси пользователя в админке: **Клиенты → Клиенты → фильтр по номеру телефона → открыть карточку клиента → блок «Бонусы» → кликнуть число под «Неактивные» → подтвердить «Да»** — для каждого телефона из списка.
3. Дождись подтверждения пользователя, что активация сделана.
4. Запусти превью второго прохода:
   ```
   python bonusplus-integration/scripts/deduct_followup.py bonusplus-integration/lists/deduct_<дата>_plan.json
   ```
   Если в выводе остались строки `ЕЩЁ НЕ АКТИВИРОВАНО` — часть клиентов не активирована, сообщи пользователю какие именно, не выполняй списание по остальным раньше времени (можно списать только тех, кто уже активирован — скрипт сам это разделит).
5. После подтверждения пользователем — выполни списание:
   ```
   python bonusplus-integration/scripts/deduct_followup.py bonusplus-integration/lists/deduct_<дата>_plan.json --execute
   ```

## Шаг 4 — финальная сверка

Посчитай и покажи пользователю: сколько всего было запрошено к списанию, сколько реально списано (сумма шагов 2 и 3), и список клиентов (если остались), у которых списание неполное **и** `pending == 0` — по ним больше ничего сделать нельзя прямо сейчас (нет ни активного, ни ожидающего баланса), это нужно явно проговорить пользователю как остаток, который можно будет доудержать только когда/если у клиента появятся новые начисления.

## Справочно — API БонусПлюс

- База: `https://bonusplus.pro/api`, авторизация `Authorization: ApiKey <ключ в Base64>`, лимит 3600 запросов/час.
- `GET /customer?phone=` — `availableBonuses` (активные), `notActiveBonuses` (ожидающие).
- `PATCH /customer/{phone}/balance` `{"amount": <дельта, отрицательная = списание>}` — единственный документированный способ менять активный баланс.
- Полная документация: `https://bonusplus.pro/api/Help`.
